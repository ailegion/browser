# Risks and Open Items

them within the crate rule and record the result here; only escalate to the
owner if resolving one would contradict a decision in `01-decisions.md`.

| O12 | **Floats and line boxes. Done 2026-09-26 (Phase 2 item 0).** taffy 0.14 positions floats and already narrows boxes that establish their own formatting context beside them, but inline roots are same-context blocks, so their lines overlapped floats. Now, after the first taffy pass, `layout` walks the laid-out tree, numbers block formatting contexts (flex, float, absolute, non-visible overflow isolate), finds the floats of each inline root's context that overlap it, and hands them to the root as bands. The root then breaks lines with parley's per-line API (`BreakLines` with `set_line_x` / `set_line_max_advance` per line): each line takes the gap at its top, and a line whose gap fits none of its content moves below the nearest float, as CSS 2.2 §9.5 says. A second taffy pass then moves the content below the taller roots; up to three extra passes if a float itself moves. Float-free pages take one pass, unchanged. Not done: floats inside inline content (a floated `<img>` in a paragraph becomes a block sibling of the surrounding text, so it sits below the line it was on) and block-level replaced elements beside floats, both Phase 5. | Done |
| O13 | **Cascade performance.** Rules are bucketed by the rightmost compound selector (id, class, tag, universal). Measured 2026-09-26 on the Wikipedia Rust article (19,295 nodes, 230 KB CSS): release build 213 ms cascade + 38 ms layout; debug build about 2 s + 170 ms. Good enough until Phase 2 adds per-subtree invalidation; ancestor bloom filters (supported by `selectors`) are the next lever if needed. Measured 2026-09-27 on the IANA IDN tables page (373,512 nodes, 146,924 elements, 169,817 whitespace-only text nodes): release 1.3 s cascade + 1.6 s layout per pass, two passes on load; a debug build takes tens of seconds, which reads as a hang. Layout already skips the whitespace-only runs. Levers when this matters: the bloom filter, and for debug builds `opt-level = 1` on our own crates in the dev profile (owner's call). | Phase 5 |
| O15 | **Interaction restyle cost. Resolved 2026-09-27.** Measured on the Wikipedia Rust article after item 4 made revisits instant: a hover change that crossed containers recomputed thousands of elements, about 1.5 s in a debug build and 100 ms in release, and every pointer move did it again, so a debug build froze under the mouse. Two changes. (1) `crates/style`: `Stylist::interaction_deps` now also records the subject key (id, else first class, else tag, else universal) of every selector that has a state pseudo-class to the left of a combinator or inside `:has()`; `restyle` recomputes only the elements whose state changed, the elements in reach whose key matches, and the descendants of any element whose computed style did change (inheritance, which the old `Reach::Element` path missed). A pseudo-element does not end the subject compound, otherwise every `::before` rule makes the key universal, which is what Wikipedia hit. (2) `crates/tab`: pointer moves and scrolls only mark hover dirty; `flush` evaluates hover once per event batch at the final position; clicks still resolve it at once. After: the same hover change costs about 10 ms in debug and 1 ms in release, and a burst of 50 moves costs microseconds. The rule index rebuild per restyle measured 0.15 ms in release, so it stays as is. **Second round, same day**, on `https://www.iana.org/domains/idn-tables` (373k nodes, 147k elements): a key set alone still recomputed 56,636 cells per hover (780 ms release), because `tr:hover > td` keys `td` and a first hover flips the whole ancestor chain including `html`. The scan now emits one `StateRule` per state pseudo-class: the key of the compound that carries the state (the trigger), and a scope: `Subtree(key)` for a descendant combinator, `Siblings(key)` for a sibling combinator (the parent's subtree), `Above(key)` for a `:has()` in the subject compound (the `:has()` element is an ancestor of the changed element or an earlier sibling of one), `AboveSubtree { has, subject }` for a `:has()` left of a combinator (the subjects are in that element's subtree). `restyle` applies only the rules whose trigger matches a changed element, groups the subtree walks by root, and runs parents first. Same page after: 10 elements, 5 ms release. The `Reach` per state is kept as a summary. | Done |
| O17 | **No line breaking inside Chinese, Japanese or Thai text.** parley 0.11 builds `icu_segmenter` with `compiled_data` but without the dictionary or LSTM models for those scripts, so runs of such text get no break opportunities and overflow their box. ICU4X reports it with a bare `eprintln` in debug builds (`icu_provider` without its `logging` feature): thousands of console lines on the IANA IDN page. The print is silenced by `[profile.dev.package.icu_provider] debug-assertions = false` in `Cargo.toml`. The breaking itself is Phase 5 (breadth): either enable the models through parley or icu features, if they are pure Rust data, or break between ideographs ourselves. | Phase 5 |
| O16 | **Cookie jar and cache scope. Resolved 2026-09-27 (Phase 2 item 4).** `02-architecture.md` lists cookies and cache as per-tab state, but the roadmap puts them in `net`, and `NetService` is one per browser. They are browser-wide: a login in one tab holds in another, which is what "logins survive" needs, and the Phase 4 persistence on tab close can write the whole jar. Gaps to close later, all in `crates/net`: (a) `SameSite` is stored but not enforced because `FetchRequest` has no initiating site; add one when Phase 3 puts origin and CORS checks on every fetch. (b) No public suffix list; a `Domain` attribute without a dot is refused, which stops `Domain=com` but not `Domain=co.uk`. The pure-Rust `psl` crate fits the rule if it is ever needed. (c) Redirect responses are not cached. (d) `document.cookie` arrives with Phase 3 bindings and must respect `HttpOnly`. | Done; gaps Phase 3 and 4 |

| O18 | **DOM wrappers are held strongly.** `02-architecture.md` ("DOM") says node wrappers are traced by `boa_gc` so unreachable ones are collected while the node lives. Phase 3 item 3.2 (2026-10-09) caches them in a `HashMap<NodeId, JsObject>` inside `crates/script/src/dom.rs`; boa_gc 0.22 treats a handle held outside its heap as a root, so a wrapper lives until its node is removed from the tree or the document goes away. Safe and gives wrapper identity, but a long-lived page that touches very many nodes keeps one small object per touched node until navigation. To free them earlier the map must hold `WeakGc`/ephemeron handles; check that boa_gc's weak pointers work for `JsObject` under `forbid(unsafe_code)` before switching. Owner accepted the strong map for now. | Phase 5 (memory) |

## Risks

Ordered by likelihood of stalling the project.

| # | Risk | Likelihood | Impact | Mitigation |
|---|------|-----------|--------|------------|
| R1 | Hand-written CSS engine grows without bound; every site needs one more property | Certain | Slow progress | Phase-gated property subsets; a UA sheet; ship Phase 2 as a usable no-script browser before chasing breadth |
| R2 | Web API surface in Phase 3 is far larger than any list | High | Phase 3 never ends | Bindings ordered by what unlocks the most sites; the WPT subset defines done, not completeness |
| R3 | Boa is an interpreter; script-heavy sites are slow | High | Product ceiling | Accepted. Nothing else is pure Rust. Track Boa's optimizer work; keep bindings cheap (no per-call allocation) |
| R4 | Linebender crates (vello, parley, wgpu) change APIs each release | High | Churn | Pin as a group; bump only at phase boundaries; thin adapter layer in `paint` and `chrome` |
| R5 | A parser dependency adds unsafe in a new release | Medium | Breaks D01 | `cargo geiger` gate in CI; baseline recorded in Phase 0 |
| R6 | `rustls-rustcrypto` has a timing side channel or rejects a common site | Medium | Security or compatibility | Accepted per D09; open source means community review; report upstream |
| R7 | Hand-drawn chrome takes longer than expected (text input with IME is the hard part) | Medium | Phase 2 slips | D05 records the fallback: Masonry or iced with CPU copy |
| R8 | Tables and floats missing from taffy break common layouts | Certain | Some pages misrender | Phase 5 item; write on top of taffy's grid for tables |
| R9 | Cross-platform surprises on Linux (fontconfig, portals) and macOS (Metal via wgpu) | Medium | Phase 2 CI matrix fails | Start the matrix in Phase 2, not later |
| R10 | Scope creep toward video, WebGL, extensions | Medium | Dilution | Out of scope until Phase 5 lists them; video declared out |
| R11 | Version drift between this plan and crates.io | Certain | Wasted effort | Re-resolve the set at each phase start; update `03-crates.md` |

## Explicitly out of scope

- Video decoding (no production pure-Rust decoder exists).
- WebGL and WebGPU exposure to pages.
- Browser extensions, unless a pure-Rust design that preserves D01 is found.
- Sync, accounts, telemetry, crash reporting to a server, any network
  request the user did not cause.
- OS-level sandboxing as a requirement (optional extra only, D01).
- AVIF images (decoder is C).
